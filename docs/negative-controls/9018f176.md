# Direct Git launch controls

Execution is deferred to the test-capable Acceptance lane; no RED/GREEN receipt is claimed here.

`ProcessTreeGuiSuppressionTestsGitDirectLaunchProcessTreeTests.Version_FromWindowlessConsole_CreatesOnlyTheRealGit`
runs two fresh probe processes with the same accounting apparatus. The enabled arm requires exactly one
new job process, the real Git image and no CREATE_NO_WINDOW. The control arm launches the shim by its
full path and requires three new processes and the shim image. Both assert that the probe
has a console with no window. Reverting direct resolution fails the real-image/one-process assertions;
reverting console-policy selection fails the one-process/creation-flags assertions. This control uses
lifetime job accounting, not a poll that could miss a short-lived git or conhost.

`ProcessTreeGuiSuppressionTestsGitDirectLaunchShellChildrenTests.RebaseExecAndPostRewriteHook_ResolveShAndProduceMarkers`
starts with a PATH containing only the shim directory, dotnet directory and system32, and an invalid
inherited MSYSTEM. The real-git image assertion prevents silently testing the shim. The rebase must
produce exactly two `exec:<installation system>` lines and the hook must run a nested `sh` and write
`hook:2`. Disabling environment augmentation should fail shell lookup or the exact MSYSTEM markers.

`GitExecutableResolutionTests` pins architecture layout fallback and launch-specific environment
ordering/defaults, including HOME fallback and git-bash.config MSYS composition. Removing the PATH
prepend, overwriting caller HOME/PLINK_PROTOCOL, freezing a prior environment, or omitting MSYS config
causes exact-value assertions to fail. Acceptance owns execution and any mutation receipts.
