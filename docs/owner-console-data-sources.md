# Owner console data sources

This census covers distinct backing sources consumed by `src/Mcg.AgentOrchestrator.App/Console`, including delegated reads. Locations below are console read sites or the console call that supplies a delegated reader. Repeated projections of the same source are not independent sources. **Per-workspace** means the read is restricted to the selected workspace, even if storage is physically shared; **host-wide** means it can contain other projects or describes host capacity. Paths embedded in a selected goal's receipts remain workspace-filtered evidence even when the physical artifact lives outside its state directory.

The console reads one workspace's stores. Its plain header and full-screen title identify that workspace as `home` or its registered project name. This identity is separate from host-row ownership.

## Board, decision and metadata reuse

The full-screen host owns its readers for one console instance. `SqliteStoreChangeObservation` retains a read-only connection and compares `PRAGMA data_version` on that connection, observing commits from other connections/processes, including WAL commits. A connection epoch and Windows volume/file identity distinguish reopened or replaced databases. No read transaction spans observations. Unsupported identity, unreadable/corrupt stores and ambiguous replacement return unknown and disable reuse; confirmed absence is checked again on every observation. Database-wide invalidation is deliberately conservative where no authoritative row-level signal exists.

## Row ownership and absent sources

`src/Mcg.AgentOrchestrator.App/Console/OwnerConsoleGateWhereLine.cs:27` labels the aggregate capacity record `host`. Each configured/unconfigured executor occupancy group and local occupancy group carries an owner from its running lanes' heartbeat paths. No running work means `host`; one consistently resolved owner means that project or `home`; missing or conflicting work evidence means `unknown`. A local group can aggregate several local slots and keeps `unknown` if their work has no unique proven owner. Metrics and configured capacities retain their existing meanings.

`src/Mcg.AgentOrchestrator.App/Console/OwnerFleetViewModel.cs:44` resolves fleet executor ownership from each report row's own recent attempts; `src/Mcg.AgentOrchestrator.App/Console/OwnerFleetDiagram.cs:51` displays the label. Both plain and full-screen fleet commands use this builder and renderer. Attempt IDs contain no project name and never establish an owner. The resolver uses absolute-path containment through `OrchestratorWorkspace.IsWithinDirectory`, chooses the longest state-directory match, and returns `unknown` on an equal-specificity owner conflict. Home is established only by containment in the separately resolved home state directory. It does not read heartbeat file contents.

**No console file reads stable build-slot occupancy, build-slot holder labels or a process inventory.** The `local slot N` string at `src/Mcg.AgentOrchestrator.App/Console/OwnerConsoleGateProgress.cs:171` is parsed from a conduct-event heartbeat token. It is not a build-slot-store read. Conductor liveness checks a selected lease owner rather than enumerating processes. Remote executor slots and their sync ledger are separate from stable .NET build slots. No new build-slot or process view is added.

Refresh timings and optional input traces are output artifacts, not sources read back by the console (`src/Mcg.AgentOrchestrator.App/Console/OwnerConsoleRefreshTimingsFile.cs:19`, `src/Mcg.AgentOrchestrator.App/Console/OwnerConsoleInputTraceOptions.cs:24`). In-memory view models, question tracking, notices and formatting consume the sources above rather than adding backing stores.
