# Board-fill scheduling projection

The experiment compares the full reader at base `f122e81ebc7cfabc50e1c21ceef176474e4bb7ad`, the integrated 49238cad cache at `534b124943c796e126195fc31d70aba611ee5dda`, and the scoped acquisition. Both baseline revisions have tree `28088178ff2b9bc564e45efc161381d055948a36`. The historical cache verifies a hash of all three ordered tables on a hit. A proved miss traverses the same content again to materialize it. The comparison retains that exact cache path as the full-content fallback.

| Output or effect | Consumer | Backlog scope |
|---|---|---|
| Candidate population, exclusions, change stamp and hold state | `BoardFillReadyItemSelector.EvaluateCandidates`, `ConductorBoardFillDraftStore.AlreadyDrafted`, `BoardFillContradictionHold` | Open rows in rowid order. ID and status identify candidates. Body and tags carry owner gates and refusal tags. Creation and update times, all note times and text, and note order by creation time and ID drive markers, annotations and the effective stamp. Active goals, rounds and current head remain separate inputs. |
| Readiness and first blocker | `BacklogDependencyReadiness`, source ownership checks in `ConductorBoardFillHost.CreateDefault` | Candidate outgoing edges in sequence order. Backlog prerequisites need ID, existence and status across all statuses. Claims, goal state and landing evidence come from their existing sources. Goal edges need the target ID and kind. Closed prerequisites need no body, notes or outgoing edges. |
| Membership questions, preferred ordering and final order | `BoardFillEpicMissingQuestion`, `EpicPlanStatusReader`, `EpicPlanReadySliceSelector`, `BoardFillReadyItemSelector.OrderReady` | Candidate ID and title identify questions. Open plan sources need their outgoing edges with prerequisite status or absence. Closed plan sources retain ID and status. Only ready open plan sources rank. Final order uses pin time, preferred rank, priority, landed dependencies, update time and ordinal ID. |
| Duplicate match and annotation | `BoardFillNearDuplicate`, `ConductorBoardFillHost.AnnotateNearDuplicate` | Candidate ID, title and body, then active goal text and title/body for distinct extant round sources in the inclusive preceding 24 hours. Status does not filter those references. Item references sort by ordinal ID after goal references. Candidate notes carry idempotence tokens. |
| Contradiction release, draft start and stopped-item events | `ConductorBoardFillHost`, `ConductorBoardFillDraftStore.Begin` | Release examines open rows and ordered marker notes with changed Git evidence. After a decision-relevant write, a new acquisition sees the durable note and item stamp. Draft start captures the selected item's identity and stamp. Stopped-item events use open IDs and round history. |
| Assessment, filing and stalled epic attention | `ConductorBoardFillHost.Assessment`, `ConductorBoardFillHost.FilingAdmission`, `StalledEpicAttention` | These paths have separate reads and can need a closed or missing source, full current item stamps or portfolio state. A projection intended for draft selection cannot stand in for those reads. |

The projection acquires candidates, ordered notes and edges, batched prerequisite status, and batched historical duplicate text within one read-only SQLite transaction. It preserves null pin behavior when the pin column is absent. It keeps prerequisite status and duplicate text in types separate from candidate records. The candidate mapper still carries the existing `SourceGoalId` and edge audit timestamps so the experiment reuses the full reader's mapping.

`BoardFillSnapshotMeasurementTests.Three_arms_report_cost_through_the_first_matching_scheduling_decision` emits the fixture digest, status counts and text bytes, module identity, environment, paired samples and bound SQLite plans. The synthetic 2,618-item workload uses both 687 and 1,374 open rows. The Nov 23 observation of 687 open rows and 6.73 MB on Done or Superseded rows informed the first distribution. Neither observation is a scheduling rule or pass threshold. The measurement includes fixed goal, round and plan inputs and the readiness, preferred order and duplicate consumers. Full conductor tick overhead, asynchronous assessment and filing, and live claim I/O fall outside this measurement boundary.

Use the elapsed, CPU and allocation deltas by workload and the reported CPU resolution and spread to rank the arms. The writer uses a common schema, so this comparison does not claim savings from removing revision maintenance. Selection requires parity, an absolute ordinary-workload gain beyond measurement uncertainty, and evidence through the default host. The experiment adds no maintained summary. A summary comparison would need to include setup, mutation, invalidation and recovery costs.
