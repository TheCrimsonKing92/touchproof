# Board-fill scheduling projection

The experiment compares the full reader at base `f122e81ebc7cfabc50e1c21ceef176474e4bb7ad`, the integrated 49238cad cache at `534b124943c796e126195fc31d70aba611ee5dda`, and the scoped acquisition. Both baseline revisions have tree `28088178ff2b9bc564e45efc161381d055948a36`. The historical cache verifies a hash of all three ordered tables on a hit. A proved miss traverses the same content again to materialize it. The comparison retains that exact cache path as the full-content fallback.

The projection acquires candidates, ordered notes and edges, batched status for prerequisites and outstanding questions, and batched historical duplicate text within one read-only SQLite transaction. A question whose backlog item is absent stays unresolved, even if a portfolio membership row survives. The projection preserves null pin behavior when the pin column is absent. It keeps prerequisite status and duplicate text in types separate from candidate records. The candidate mapper carries the existing `SourceGoalId` and edge audit timestamps and reuses the full reader's mapping.

`BoardFillSnapshotMeasurementTests.Three_arms_report_cost_through_the_first_matching_scheduling_decision` emits the backlog fixture digest, status counts and text bytes, module identity, environment, paired samples and bound SQLite plans. The synthetic 2,618-item workload uses both 687 and 1,374 open rows. The Nov 23 observation of 687 open rows and 6.73 MB on Done or Superseded rows informed the first distribution. The distributions are measurement inputs.

Each arm runs the same default shadow host through synchronous tick return, after the selected round has been persisted. The fixture uses real portfolio membership and plan rows, a live source claim, an open prerequisite with a completed landing journal, and both an active goal and a recent historical item that match the same candidate. It asserts the selected IDs and readiness reasons, the single persisted goal-duplicate annotation, and the committed contradiction-release note and its stamp on the selected round. The timed change starts at a committed backlog edit and includes the host's note write and reacquisition. Draft generation uses a deterministic stub which is awaited outside the timed tick. Quiet samples keep the backlog unchanged after priming while the host advances its draft history. The experimental arm uses the integrated full cache for the separate assessment and stalled-epic reads. Filing is outside the shadow workload.

Backlog acquisition and write SQL counters come from separate traced samples. The backlog read totals include the full-content fingerprint used by the integrated cache. The projection counters identify the scoped scheduling queries. The write totals combine the scripted edits with SQL on both connections opened by the host note writer, including setup, the item and note reads, and revision triggers. The receipt also breaks out the note writer's statements, trigger steps, result rows and result payload. Input note text bytes remain a separate count. Host note CPU, allocations and elapsed time are included in the tick totals, and WAL growth includes scripted edits and host note writes. The receipt compares both read-only and combined read-and-write result payload using baseline bytes minus projection bytes.

Reviewer receipt `finding-evidence-406ca978987992c99444bbce` measured revision `77929ba85c12862c9de99c7557521004e6738b99` and ranked the projection first for quiet and changed Shadow ticks at both fixture sizes. Compared with the integrated cache, paired median elapsed savings were 558–861 ms per 16 quiet decisions and 183–442 ms per five changed decisions. Every pair in those two workloads favored the projection. Cold CPU was inconclusive and the cold projection transferred 0.45–0.76 MB more than the full reader. The choice uses absolute savings on repeated Shadow ticks without weighting the scenarios or extrapolating to File mode.

The default host uses the measured projection for Shadow scheduling. It keeps the integrated fingerprint cache for File mode, assessment, and stalled-epic attention, which can consume full closed-item records. The host differential `Default_shadow_projection_matches_full_read_when_a_closed_item_is_assigned` checks both question resolution after a restart and the smaller scheduling acquisition through the default factory. The common writer schema includes revision maintenance. There is no measured net benefit to justify introducing a maintained summary with setup, mutation, invalidation and recovery costs.
